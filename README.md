# BOTT — בוט מסחר אלגוריתמי לזהב

פלטפורמת מסחר אלגוריתמי לזהב (XAU/USD): דשבורד חי עם גרף נרות, בוט מבוסס אסטרטגיות
שרץ על נתוני שוק אמיתיים, מנוע מסחר מדומה (paper trading) עם ניהול סיכון וסטופ-לוס/
טייק-פרופיט, בחירת אסטרטגיה מתוך כמה אסטרטגיות מוכרות + בניית אסטרטגיה מותאמת אישית,
פאנל מחשבות חי, יומן אישי + חוקי פידבק שמשפיעים בפועל על הבוט, וסימון אזורים על הגרף.

**מצב נוכחי**: הפלטפורמה עובדת במסחר מדומה כברירת מחדל (ללא ברוקר חיצוני, ללא
הרשמה), אך יודעת גם לסחור באמת מול OANDA או MetaTrader 5 (`app/broker/oanda.py`,
`app/broker/mt5.py`) — כולל פתיחה/סגירה/עדכון SL-TP של עסקאות אמיתיות, וזיהוי
עסקאות שנסגרו אצל הברוקר עצמו (סטופ/טייק-פרופיט/סגירה ידנית). הכל נשלט ע"י
`EXECUTION_MODE` ב-`.env` (`simulated` כברירת מחדל, `live` להפעלת ביצוע אמיתי) —
כך שהמעבר לכסף אמיתי הוא תמיד החלטה מכוונת, לעולם לא בטעות.

## מבנה הפרויקט

```
BOTT/
├── backend/    FastAPI + Python — נתוני שוק, מנוע אסטרטגיות, מסחר מדומה, API
└── frontend/   React + Vite + TypeScript + lightweight-charts — 3 מסכים
```

## מסכים

- **מסחר** (`/`) — גרף נרות חי (1/5/15 דקות, שעה) עם קווי SL/TP וסמן כניסה לעסקה
  הפתוחה, אוברליי אינדיקטורים (EMA/SMA/רצועות בולינגר — לפי האסטרטגיה הפעילה),
  בחירת אסטרטגיה, מתג הפעלה/כיבוי, פס פוזיציה פתוחה, פאנל מחשבות חי, ופאנל
  יומן+חוקים (עם אפשרות לסמן אזור על הגרף ע"י גרירה ולצרף אליו הערה).
- **הגדרות** (`/settings`) — מתג הפעלה, ניהול סיכון (גודל עסקה, מספר פוזיציות
  מקסימלי), רשימת אסטרטגיות + יצירת אסטרטגיה מותאמת אישית (חציית שני אינדיקטורים
  עם תקופות/SL/TP משלך).
- **תיק** (`/portfolio`) — סטטיסטיקות (אחוז הצלחה, רווח/הפסד כולל, ירידה מקסימלית),
  עקומת הון, והיסטוריית עסקאות מלאה.

## הרצה — Backend

לפני הרצת השרת המלא (אם עוברים ל-OANDA), כדאי לוודא שהחיבור עובד עם סקריפט עצמאי:

### מקור נתונים: OANDA או Yahoo (ב-`backend/.env`)

- **`DATA_SOURCE=yahoo`** — בלי הרשמה בכלל. נתוני חוזי זהב (GC=F) אמיתיים אך
  read-only — טוב להדגמה מיידית של הגרף החי, אבל **מנוע המסחר המדומה כבר עובד גם
  איתו** (הביצוע קורה אצלנו, לא אצל ברוקר, כך שאין צורך ב-OANDA כדי לראות את הבוט
  פותח/סוגר עסקאות).
- **`DATA_SOURCE=oanda`** — חשבון **OANDA v20 Practice** (דמו, חינמי):
  1. הרשמה ב-oanda.com.
  2. My Account → Manage API Access → Generate Personal Access Token.
  3. למלא ב-`.env`: `OANDA_API_TOKEN`, `OANDA_ACCOUNT_ID` (למשל
     `101-004-1234567-001`), ולהשאיר `OANDA_ENVIRONMENT=practice`.
  4. שים לב: כברירת מחדל **ביצוע העסקאות עדיין מדומה** גם כש-OANDA הוא מקור
     הנתונים (הפרדה בין "מקור נתונים" ל"ברוקר ביצוע" — ראה `app/broker/factory.py`
     ו-`app/order_service.py`). כדי לסחור אמיתית מול OANDA צריך גם
     `EXECUTION_MODE=live` (ראה בהמשך).

- **`DATA_SOURCE=mt5`** — מתחבר לטרמינל **MetaTrader 5** שכבר מותקן, פתוח, ומחובר
  לחשבון (דמו או live) על המחשב הזה. בניגוד ל-OANDA זה לא API מרוחק — אין הרשמה
  דרך הקוד, רק צריך שהתוכנה של MT5 תהיה פתוחה ומחוברת ברקע.
  1. ודאו שה-Algo Trading (הכפתור הירוק בסרגל הכלים של MT5) פעיל בטרמינל.
  2. ב-`.env`: `DATA_SOURCE=mt5`, `MT5_SYMBOL=XAUUSD` (או שם הסימבול המדויק אצל
     הברוקר שלכם — אפשר לבדוק ב-Market Watch).
  3. אם `MT5_LOGIN` נשאר `0`, האדפטר פשוט מתחבר לחשבון שכבר מחובר בטרמינל —
     אין צורך למלא פרטי משתמש/סיסמה בקובץ.
  4. **הגנה מובנית**: אם הטרמינל מחובר לחשבון **live** (לא דמו), האדפטר מסרב
     להתחיל אלא אם `ALLOW_LIVE_TRADING=true` נקבע במפורש — בדיוק כמו ב-OANDA.
  5. לבדיקת החיבור בלבד (read-only, לא פותח שום עסקה):
     `./venv/Scripts/python scripts/test_mt5_connection.py`

### ביצוע עסקאות אמיתי (`EXECUTION_MODE`)

`EXECUTION_MODE=simulated` (ברירת מחדל) — כל עסקה נפתחת/נסגרת רק בברוקר המדומה
הפנימי, בלי קשר ל-`DATA_SOURCE`. `EXECUTION_MODE=live` מעביר את הביצוע בפועל
לברוקר האמיתי (`DATA_SOURCE=oanda` או `mt5` בלבד — עם כל אחר השרת מסרב לעלות):
עסקאות נפתחות/נסגרות אצל הברוקר עצמו, וה-SL/TP מנוהל בצד השרת שלו. הבוט מזהה
עסקאות שנסגרו שם (סטופ, טייק-פרופיט, או סגירה ידנית בטרמינל) ע"י השוואה בין
העסקאות הפתוחות שלנו במסד הנתונים לבין הפוזיציות הפתוחות בפועל אצל הברוקר, בכל
נר שנסגר (`OrderService._reconcile_live`).

על חשבון **live** אמיתי (לא דמו), הפעלת `EXECUTION_MODE=live` דורשת גם
`ALLOW_LIVE_TRADING=true` — בלעדיו האדפטר (OANDA/MT5) מסרב לעלות מלכתחילה.
מומלץ בחום לבדוק על חשבון **דמו** לפני מעבר לחשבון live.

### הערה על Netspark

על המחשב הזה מותקנת תוכנת סינון תוכן (Netspark) שמיירטת תעבורת HTTPS. הקוד משתמש
בחבילת `truststore` (ב-`app/__init__.py`) כדי לסמוך על מאגר האישורים של מערכת ההפעלה
במקום מאגר ה-CA המובנה של Python, כדי שחיבורי HTTPS יעבדו דרך המיירט. אם מריצים את
הפרויקט הזה על מחשב אחר בלי תוכנת סינון כזו, `truststore` פשוט לא עושה כלום מזיק.

## ארכיטקטורה (תמצית)

- **`app/broker/`** — שכבת ברוקר מופשטת: `base.py` (ממשק), `oanda.py` ו-`mt5.py`
  (נתונים+ביצוע אמיתי מלאים — פעילים בפועל רק כש-`EXECUTION_MODE=live`, ראה
  למעלה), `yahoo.py`/`twelvedata.py` (נתונים בלבד, ללא הרשמה), `simulated.py`
  (ביצוע מדומה — fill מיידי, בדיקת SL/TP לפי טווח הנר). `factory.py` בוחר לפי
  `DATA_SOURCE`.
- **`app/strategies/`** — 5 אסטרטגיות מובנות (MA crossover, RSI, MACD, Bollinger,
  ATR trend) + `rule_based.py` (מפרש DSL הצהרתי ל-JSON לאסטרטגיות מותאמות אישית,
  בלי הרצת קוד). `registry.py` מרכז את כולן.
- **`app/strategy_engine.py`** — מריץ את האסטרטגיה הפעילה על כל נר סגור, שומר
  ומשדר "מחשבה", ומעביר איתותים ל-`order_service.py`.
- **`app/order_service.py`** — הצומת היחיד שמחליט אם איתות הופך לעסקה בפועל: בודק
  מתג הפעלה, הגבלות סיכון, וחוקי פידבק פעילים (`app/feedback_rules.py` +
  `app/condition_dsl.py` — אותו דקדוק תנאים גם לאסטרטגיות מותאמות אישית).
- **`app/db.py` / `app/models.py`** — SQLite עם SQLModel (מחשבות, עסקאות, הגדרות,
  אסטרטגיות מותאמות, יומן, חוקי פידבק).
